RNA - Ritvij Naram Assistant

A local-first personal AI assistant that combines Ollama inference, persistent JSON memory, web search, file reading, and document generation behind a browser and terminal interface.

01 / overview

Build an assistant where the model is only one component.

RNA explores a tool-using assistant architecture in which chat, memory, search, file understanding, and document generation are separate capabilities coordinated by a local Node.js application. The core premise is privacy: inference and conversation state stay on the user’s machine.

01100% local inference

Ollama runs phi3:mini locally, avoiding a cloud model dependency for chat.

02Persistent memory

JSON persistence tracks user/session information and recent conversation context.

03Tool layer

Web search, file reading, and PDF/Word/Excel generation extend the assistant beyond chat.

02 / architecture

A local orchestrator around the language model.

The Express application exposes a browser interface while RNA’s orchestration layer decides when to use local inference, memory, or a specialized tool.

system_viewarchitecture / data flow

The model does not directly own every capability. A local orchestration layer keeps memory and tools modular, making the assistant easier to extend and reason about.

03 / flow

How a request moves through RNA

A user request can stay as a simple local chat or invoke additional capabilities when needed.

01Receive request

Browser or CLI sends the user message to the local server.

02Load context

RNA loads relevant recent messages and persisted session memory.

03Route capability

Choose local model response, web search, file reading, or document generation.

04Execute locally

Ollama and Node.js tools perform the requested work.

05Return + persist

Response is shown and conversation state is saved for the next session.

04 / capabilities

05 / decisions

Key engineering decisions

  • Local-first inference - Ollama keeps the core conversation private and removes per-request API cost.
  • Modular tools - search, file reading, document creation, and memory live in separate modules rather than one large assistant file.
  • Dual interface - the same assistant can be used through the browser UI or terminal mode.
  • Simple persistence for a personal tool - JSON is sufficient for the current single-user scope while keeping the project easy to inspect.
