Pitch Predictor — FIFA World Cup 2026

Private source · Live deployment · JavaScript · Firestore · GitHub Actions · Netlify
Open live experience ↗ Source repository private

The idea

Pitch Predictor turns the FIFA World Cup 2026 into a campus-wide participation game. Students scan a QR code from university screens, enter the experience without installing an app, predict Home / Draw / Away results before kickoff, and compete on a leaderboard that updates after matches finish.

The engineering goal was not just to build a prediction form. The system needed to stay online continuously, synchronize phones and public displays in realtime, close predictions exactly at kickoff, ingest final results automatically, and operate without a traditional application server that needed monitoring.

How the automation works

Predictions are editable only before kickoff. Once a match starts, the UI locks that fixture. A scheduled GitHub Actions workflow runs a Node.js results bot every 15 minutes. The bot checks matches that are awaiting a result, requests final scores from API-Football, and writes the winner to Firestore. Realtime listeners then propagate the update to connected phones and campus displays, where points, streaks and leaderboard ordering recalculate automatically.

Product features

  • QR-first onboarding — a student can move from a campus screen to the prediction experience without an app install.
  • Kickoff-aware locking — predictions automatically close to the second when the match begins.
  • Realtime leaderboard — total correct picks, current streak, best streak and accuracy drive the ranking.
  • Automatic results — no administrator needs to manually enter every finished match.
  • Track record — each participant can see which matches they predicted correctly.
  • Display mode — a projector-friendly interface keeps the QR code and top predictors visible on campus screens.
  • Staff controls — passcode-gated controls manage fixtures, people, results and settings.

Engineering decisions

  • Static frontend instead of a permanent web server. The core experience is a single browser application, which keeps deployment simple and removes server maintenance from the operational model.
  • Firestore for synchronization. Realtime listeners let student phones and public displays react to the same state changes without building custom websocket infrastructure.
  • GitHub Actions as scheduled backend automation. A cron-triggered Node.js job handles result ingestion while keeping the main application serverless from an operations perspective.
  • Quota-aware external API usage. The bot only requests football data when a match is actually waiting for a result, minimizing unnecessary calls and keeping the design suitable for free-tier infrastructure.
  • Game mechanics separated from participation. Skipping a match does not break a streak; only an incorrect prediction does, making the scoring model less punitive for occasional participants.

Scoring model

A correct Home / Draw / Away prediction earns one point after full time. Ranking prioritizes total correct picks, then best streak, then accuracy. Current and best streaks are tracked independently so the leaderboard captures both consistent participation and standout prediction runs.

Deployment model

The project combines Netlify hosting, Firebase Firestore, GitHub Actions and API-Football. The application is designed to remain available even when the development machine is offline, which was important for an always-on campus-screen experience.

Project status

The group-stage experience includes the full 72-match fixture set, automated result retrieval, streaks, celebrations and participant history. The roadmap includes dynamically adding knockout rounds as the tournament bracket is decided, plus optional audience-specific leaderboard views and push notifications.
