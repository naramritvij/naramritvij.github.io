Anomaly Detection for Video Surveillance

A Python desktop application that authenticates users, reads MP4 surveillance video frame by frame, preprocesses each frame for a Keras CNN, and displays normal/anomalous classifications through a Tkinter interface.

01 / overview

Reduce manual video review to a focused classification pipeline.

The project demonstrates an end-to-end desktop inference workflow: authenticated access, video selection, frame extraction, deterministic preprocessing, CNN classification, and real-time visual annotation.

01Frame-by-frame inference

MP4 video is processed sequentially rather than uploaded to an external service.

0264 × 64 grayscale input

Frames are resized, converted to grayscale, normalized, and reshaped for the trained model.

03Controlled access

Registration and login are persisted in SQLite before the detection dashboard is available.

02 / architecture

Authentication and inference are separate application paths.

SQLite is used for user access, while OpenCV and Keras form the video-analysis path inside the desktop application.

system_viewarchitecture / data flow

The database does not store detection events in the current implementation; its role is user authentication. The inference pipeline remains file-based and local.

03 / flow

Frame-level inference pipeline

Every frame is transformed into the input shape expected by the saved Keras model.

01Authenticate

User registers or logs in before opening the detection dashboard.

02Read frame

OpenCV reads the selected MP4 one frame at a time.

03Preprocess

Resize to 64×64, convert to grayscale, normalize, and reshape.

04Predict

The saved CNN classifies the frame as normal or anomalous.

05Annotate

Frame number and detection label are drawn on the displayed video.

04 / model input

The model sees a normalized grayscale tensor, not the raw video frame.

05 / decisions

Key engineering decisions

  • Frame-level model - keeps the inference pipeline straightforward and computationally lighter than a temporal video model.
  • Local desktop workflow - Tkinter and OpenCV allow direct file analysis without deploying an application server.
  • Explicit preprocessing - the exact resize, grayscale, normalization, and reshape sequence makes model expectations transparent.
  • SQLite only for access control - authentication state is persisted without adding an external database dependency.
current limitations

The repository notes missing background-image assets and a hardcoded model path that should be converted to a portable relative path. The classifier is frame-based, so it does not model temporal context across frames.
