CivicFlow AI

A full-stack incident intelligence platform that combines React, FastAPI, Oracle, and Gemini to turn operational transit incidents into structured AI analysis, recommendations, passenger messaging, and executive summaries.

01 / overview

Put AI around operational data without making AI the system of record.

CivicFlow AI separates persistent incident data from generated analysis. Oracle stores incident state, FastAPI controls application logic and AI usage, Gemini creates structured intelligence, and the frontend presents both operational records and generated insight.

01Structured incident intelligence

Severity, root cause, recommended actions, passenger messaging, executive summary, and confidence.

02Controlled AI usage

Cached responses and daily API usage limits reduce unnecessary model calls.

03Relational backbone

Oracle remains the authoritative data layer for incidents and application state.

02 / architecture

Operational data and AI analysis stay separated.

The API layer mediates both the relational database and Gemini so the browser does not directly own business logic or AI credentials.

system_viewarchitecture / data flow

FastAPI is the control plane: it retrieves incidents, checks cached AI state and usage limits, invokes Gemini only when needed, and persists the resulting structured analysis.

03 / flow

From incident record to decision support

Generated intelligence is tied back to an existing operational record rather than living as an isolated chatbot response.

01Retrieve incident

The dashboard requests an operational incident through FastAPI.

02Check AI state

Backend checks cache and daily model-usage constraints.

03Analyze

Gemini returns structured severity, cause, actions, messaging, and confidence.

04Persist

Analysis is cached alongside the incident workflow.

05Present

React renders actionable operational and executive views.

04 / AI output

The model returns structured operational fields, not a generic chat response.

This makes the AI output easier to cache, review, display, and reuse inside an incident workflow.

05 / decisions

Key engineering decisions

  • API-owned orchestration - FastAPI keeps database access, model calls, caching, and usage rules out of the browser.
  • Structured AI output - the model produces defined operational fields rather than unbounded prose.
  • Caching and usage limits - repeated analysis can reuse prior results while limiting unnecessary external API calls.
  • Relational system of record - AI enriches the workflow, but Oracle remains authoritative for incident data.
